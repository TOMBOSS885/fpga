# RTL API Agent 设计与验证记录

## 状态

日期：2026-10-19。基于当前开发分支 `868b44d` 的官方接口约束和既有经验，新建独立方案包。没有合并 PR5，也没有改动原 agent、官方 example、selftest、tasks 或全局 skills。

这是可配置、可测试的工程实现，当前没有真实模型部署、AMD GPU、Vivado 或官方基础镜像实测结果。不能据此声称“最佳 agent”、官方 L3 通过率、技能增益、显存峰值或比赛得分。模型信息保留为待填。

## 架构与改进

| 环节 | 设计 | 目的 |
| --- | --- | --- |
| 输入 | 仅读取题面和可选接口；从题面端口列表建立契约 | 适应正式 RTL 输入的空 interface |
| 生成 | 模型直接根据原始规格生成 DUT，不先用另一轮模型重写题面 | 减少串行开销与规格漂移 |
| 技能 | 官方接口契约技能，加团队已有的算术、复位、优先级、FSM、移位、锁存器技能 | 按需加载，有界上下文 |
| 工件 | 保留目标模块、必要辅助模块、宏、package 和类型前缀；剔除测试模块 | 处理常见模型代码包装，避免丢失 helper |
| 编译 | xvlog → xelab，带官方环境要求的 timescale | 真实编译后才记录内部 L1 |
| 自测 | 初次仅给规格，不给 DUT；模型生成独立参考和固定输入序列 | 降低复制 DUT 缺陷的风险 |
| 修复 | TB 编译错误只修 TB；功能差异允许依据原题判断修 DUT 或 TB | 避免错误测试台反向破坏正确 RTL |
| 综合 | Vivado OOC、ZU3EG、5ns 参数，检查完整成功标记 | 综合未完成时不误报通过 |
| 回退 | 原子写入已达里程碑的产物；失败修复不能覆盖更高等级版本 | 超时或服务异常保留可交付代码 |
| 预算 | 单调时钟总预算，模型 HTTP 独立进程限时，EDA 进程树清理 | 限制慢响应和孤儿工具进程 |
| 轨迹 | 模型调用、参数上限、usage、摘要、工具日志、产物 SHA-256 | 可追踪生成、验证与最终交付关系 |
| 部署 | 标准 HTTP、环境变量、密钥文件、原版基线鉴权转发 | 同时支持本地与远程 AMD 模型服务 |

自测生成有自己的模型请求预算，不再扣进固定的仿真阶段预算。缺少可信的本地 oracle 时仍可检查综合，但只报告“编译/综合通过、功能未验证”，不会跨级标成内部 L3。

同一源码已在本次 solve 中编译通过时可复用编译结果；修改源码后必须重新编译。上下文每轮重建，只保留完整原题、当前代码、相关技能与当前错误，不累积整段历史对话。

## 验证性质

测试使用标准库 unittest，包含真实本地 HTTP 请求和子进程执行，不依赖付费 API。

当前本机回归：43 项中 41 项通过，2 项原生测试因未启用 Vivado 环境而跳过，0 失败/错误；记录见 `tests/VALIDATION.md`。脚本语法、manifest JSON、包结构、官方基线和接口 skill 字节校验均通过。

- 接口：官方题面列表、signed、参数化和共享方向端口、老式端口声明、缺失端口。
- 工件：辅助模块、宏和类型前缀保留；思考段、截断产物和测试模块处理。
- 远程协议：Bearer、分段 content、SSE、401 不重试、慢速分块响应的总超时。
- 工具判定：成功 license 日志、非零退出、失败覆盖成功、重复/缺失/零比较 verdict。
- 调度：独立验证提示不含 DUT；TB 单独修复；缺少 oracle 时综合但不冒充功能通过；回退与最终摘要。
- 服务：令牌、模式校验、原版基线摘要、固定采样、单次调用、真实显存指标条件、假 EDA 协议整链路。
- 原生测试：正确 8 位取反器通过穷举；恒零变异设计失败；正确设计 Vivado 综合。只有显式设置 `RTL_NATIVE_TESTS=1` 才执行；当前机器未运行。

假 EDA 测试验证调用和控制流，**不验证 RTL 语义，也不是官方 L3 实测**。真实统计需要在同一模型后端运行官方 baseline 与本方案，再用官方 selftest 和独立参考判定；公开题、开发题和未见题要分别报告。

## 参考与设计取舍

- [OpenCode agents](https://opencode.ai/docs/agents/)：参考角色分工与有界步骤设计；本包没有引入其终端 UI 或运行依赖。
- [Pi](https://github.com/earendil-works/pi/tree/main/packages/coding-agent)：参考小核心、外部模型和按需技能组织。
- [SWE-agent 论文](https://arxiv.org/abs/2405.15793)及[轨迹说明](https://swe-agent.com/latest/usage/trajectories/)：参考工具反馈、结构化观测与可检查轨迹。
- [VerilogCoder 论文](https://arxiv.org/abs/2408.08927)：参考编译、仿真、错误反馈的 RTL 修复思路；本包没有实现该论文的 AST 波形追踪，也不引用其成绩作为本包成绩。
- 比赛来源：`AMD.pdf`、`rtlagent2026/SCORING.md`、`docs/API_CONTRACT.md`。PDF 中的较早工具版本与后续仓库环境说明有差异，因此运行路径由基础镜像变量提供，最终以赛事公告和镜像为准。

这是基于这些来源作出的工程选择，是否提高真实通过率仍需实验比较。

## 已知边界和正式提交前剩余工作

1. 真实模型未选定、未部署；权重版本、量化、AMD 后端兼容、单卡显存、冷启动和长时间服务尚待实测。
2. 生成式 oracle 会误读规格、漏测或错误计数。结构检查和 `checks>0` 不是语义证明；内部功能通过不能替代隐藏参考判定。
3. SystemVerilog 契约处理是保守的轻量解析，不是完整语法树。复杂类型、宏条件或未解析表达式仍需编译器/外部参考检测。
4. tokenizer 估计不是精确计数；输出截断后仅保留完整模块，缺失 helper 会在编译阶段暴露。应按实际模型调上下文和输出预算。
5. Docker、正式断网环境、GPU 连续请求与原生 Vivado 测试尚未在当前机器验证。该包完成工程交付，不等于已经满足最终参赛验收。
6. 客户端能限制 HTTP 等待并关闭连接；远程模型后端是否随断连取消 GPU 生成，由该后端决定。进程隔离和少量静态限制也不等于操作系统级 RTL 执行沙箱。
